# Consultant Graph Tool

**Reusable, evidence-driven execution graphs for enterprise consultants.** The first scenario pack investigates synthetic SAP S/4HANA sales order shipping point and route determination. LangGraph performs the actual branching, retries, checkpointing and review; deterministic Python rules supply the SAP-specific diagnoses.

[Architecture decisions](ARCHITECTURE.md) · [Source workflow](src/consultant_graph_tool/engine.py) · [SAP Shipping adapter](src/consultant_graph_tool/sap_shipping.py) · [Interactive browser demo](docs/index.html)

> Educational prototype only. All records and configuration are synthetic. No SAP access, no LLM account, no production data, and **no write operations**.

## Quick start

Requires Python 3.11 or newer.

```bash
git clone https://github.com/dkharlanau/Consultant-Graph-Tool.git
cd Consultant-Graph-Tool
python -m pip install -e ".[dev]"
cgt list
cgt run no-route-rule
pytest -q
```

To view the execution graph as an interactive replay:

```bash
cgt export-traces --output docs/traces.json
python -m http.server 8000 --bind 127.0.0.1 --directory docs
# Open http://127.0.0.1:8000
```

Alternatively, start everything with **`make demo`** (installs the package, exports the traces and serves the page) or **`docker compose up --build`** (then open http://127.0.0.1:8000).

The replay file is **not hand-authored**: it is generated by executing the same compiled Python/LangGraph workflow used by the CLI and tests. The website only steps through that recorded trace. It does not execute Python, contact SAP, or generate AI responses.

## Publish the browser demo on GitHub Pages

This repository includes an **opt-in** workflow at `.github/workflows/pages.yml`. After merging the implementation into `main`, enable GitHub Pages in **Settings → Pages → Build and deployment → GitHub Actions**. Then open **Actions → Publish Consultant Graph Tool demo → Run workflow**. The workflow installs the real graph package, generates a fresh trace bundle and deploys only the static `docs/` directory. It does not require an LLM account or SAP connection.

Until the Pages workflow has successfully deployed, the browser demo is available locally or as the `consultant-graph-tool-site` artifact from a successful CI run. Do not treat a proposed Pages URL as a confirmed live deployment.

## Useful commands

| Command | What it does |
| --- | --- |
| `cgt list` | See all 14 synthetic diagnostic cases |
| `cgt run happy-path` | Run a valid shipping point/route scenario |
| `cgt run no-route-rule` | Inspect a configuration gap and linked evidence |
| `cgt run transient-source-error` | See a source retry and recovery |
| `cgt run persistent-source-error` | Stop after the bounded retry budget |
| `cgt run no-route-rule --review` | Pause at a real LangGraph human interrupt |
| `cgt run no-route-rule --review --decision approve` | Resume that paused run **in the same process** |
| `cgt run no-route-rule --review --decision reject` | Reject the proposal (without any SAP changes) |
| `cgt graph` | Print the stable logical graph inventory as JSON |
| `cgt export-traces --output docs/traces.json` | Prepare the offline browser demo |

The review in v0.1 is an approval of a **diagnostic recommendation**, not an authorization to change data. The in-memory checkpointer supports suspension and resumption within a single process; it does not persist reviewer identities or decisions across restarts.

## What the SAP pack demonstrates

The first release covers the narrow *classic sales-order determination* pattern, not every SAP S/4HANA configuration variant. In the simplified scenario:

- The shipping point proposal depends on delivering plant, shipping condition, and material loading group.
- The route proposal depends on departure country/zone from the effective shipping point, destination country/zone from ship-to, shipping condition, and material transportation group.
- A manually assigned alternative shipping point is **not automatically treated as invalid**.
- A missing synthetic rule triggers investigation of the corresponding configuration, not an invented SAP setting.

The pack includes missing master data, missing rules, duplicate rules, manual overrides, successful determinations, temporary source errors and permanent failures. Each finding has a category, business owner, suggested action and evidence reference IDs. Each node produces a bounded trace with the current state.

Read authoritative SAP references: [Shipping Points](https://help.sap.com/docs/SAP_S4HANA_ON-PREMISE/c7894a248ca14f74aca67f97528e5ad7/5d1bbf53d25ab64ce10000000a174cb4.html) and [Route Determination](https://help.sap.com/docs/SAP_S4HANA_ON-PREMISE/c7894a248ca14f74aca67f97528e5ad7/601bbf53d25ab64ce10000000a174cb4.html). SAP Cloud editions, configuration variants, document overrides and extensions may differ.

## Workflow

```text
                     +---- retry (max 3) ----+
                     |                       |
START -> load -------+--> validate -> analyze -> diagnose -> verify
          |                 |                      |          |
          |                 +------ invalid ------+          +-- review requested --> review
          |                                               |                            |
          +-- source exhausted --> report <---------------+----------------------------+
                                   |
                                  END
```

The engine separates **workflow state and transitions** from **scenario-specific data and rules**. The default execution requires no AI model because SAP master-data and customizing rules should be evaluated deterministically. In a future release an LLM may help explain validated evidence, but it must not fabricate missing business facts.

## Add another consultant scenario

Implement the `ScenarioPack` protocol defined in [`engine.py`](src/consultant_graph_tool/engine.py): `name`, `list_cases()`, `get_case()`, `validate()`, and `analyze()`. Register the new pack in `cli.py`, supply synthetic fixtures and tests, and run `cgt export-traces` for its replay file.

Candidate packs: MDG Business Partner replication, pricing-condition diagnosis, AIF/IDoc troubleshooting, migration reconciliation, and architecture decision checks. These are **possible future extensions**, not shipped features.

## Verification and boundaries

GitHub Actions installs the official `langgraph` package, runs scenario tests and human-review tests, exercises the CLI, generates a static trace bundle and checks the browser JavaScript syntax. Published traces must always originate from the Python workflow.

The project does **not** currently include: a live SAP connector, automatic correction of master data, arbitrary no-code graph editing, LLM-based reasoning, a persistent approval database, real-time browser execution, or enterprise authentication.

Security rules: use synthetic data in this public repository; do not commit credentials, client extracts, real Business Partner details or proprietary configuration.
